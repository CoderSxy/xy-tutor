# 知识点库替换教材输入与会话绑定

- 日期：2026-11-10
- 状态：方案已确认，待用户审阅本文后进入实施计划；本文不代表功能已经实现。
- 范围：用管理员知识点库替换教材上传与解析；学生会话不再绑定年级、科目和教材；辅导答疑与出题按问题检索已发布知识点。
- 用户确认：独立知识点库；一次上传可由 AI 拆成多条，管理员确认后发布；已发布知识点对所有学生开放，学生不用选择，agent 按问题自动检索；教材上传、解析和年级科目绑定一并下线；旧教材表保留但不对学生开放。
- 实现约定：代码实现默认使用本机 Claude Code，模型走 https://api.nerosun.cn。

## 1. 目标与边界

管理员上传文本、图片或文件后，系统先做 AI 解析总结；真正入库并供辅导使用的是管理员确认后的总结内容，不是原始教材分页。管理员可修改总结，也可补充提示词重新解析后再确认。学生登录后直接进入学习，不再选择年级、科目或教材。agent 在处理问题、回复和出题时检索已发布知识点；找不到依据时明确说明依据不足，不编造。

本次不做：向量检索（库明显变大后再考虑）；把原始上传文件直接交给学生当教材；自动把待确认条目对学生发布；迁移或删除旧教材表数据；班级、年级或科目维度的权限隔离。

验收底线：未确认条目对学生和检索不可见；新会话不要求教材版本；教材选择与教材管理入口已关闭；重新解析不覆盖已发布内容，须再次确认。

## 2. 现状与方案选择

### 2.1 已核对的实现

当前管理员上传 PDF 教材，后台 `textbook.parse` 解析为页面和 chunks，审核后发布教材版本。学生通过 `student_selections` 绑定年级、科目和 `textbook_revisions`。会话、学习任务、学情观察、题目和 `search_textbook` 工具都绑定 `revisionId`。学情里已有的 `knowledge_point` 字段是学生掌握度标签，不是管理员维护的知识点内容库，本次不复用那张表来存教材替代物。

### 2.2 备选与决定

1. 独立知识点库 + 确认发布 + 关键词检索（采用）：与旧教材模型解耦，符合「总结入库、确认后开放、按问题检索、会话解绑」。旧表先保留，避免本次做破坏性删库。
2. 把知识点塞进现有教材/分页结构：可复用 `search_textbook`，但年级科目、分页校对和教材发布流程会继续缠在一起。
3. 每次把全部已发布知识点注入模型上下文：条目少时简单，库变大后不稳定，也不适合 2G ECS。

部署仍使用现有 React/Vite、Fastify、PostgreSQL/Drizzle、ModelGateway 与 JobQueue；不新增基础设施。检索第一期用标题和总结的关键词检索，每次只返回少量最相关已发布条目。

## 3. 数据模型

新增独立表，不改写教材旧表用途，也不删除它们。

- 上传批次：一次管理员提交（纯文本、一张或多张图片、一个或多个文件，或组合）。保存原文或文件引用、上传者、时间。源文件只作解析依据。
- 解析任务：关联批次、可选补充提示词、所用模型、状态（queued/processing/succeeded/failed）、失败原因。一次重新解析创建新任务，不改写旧任务记录。
- 知识点条目：标题、总结正文、状态（pending_review / published / discarded）、来源批次、产生它的解析任务、可选的「取代中的已发布条目」指针、创建和更新时间。确认后变为 published；管理员丢弃为 discarded。
- 已发布条目被重新解析时：新结果生成为 pending_review，不直接覆盖 published 正文。管理员确认后，就地更新该已发布条目的标题与总结；以往解析任务记录保留，便于对照。

每条对学生可见的内容必须是确认后的标题和总结。原文、中间 OCR/抽取文本和提示词只给管理员查看。

现有 `conversations.revision_id`、`learning_tasks.revision_id` 等外键：新会话和新任务不再要求教材版本（字段改为可空或停止写入）。打开仍带旧 `revision_id` 的会话时，按未绑定会话处理，不再查询或展示教材内容。学生掌握度等仍引用教材版本的历史数据可保留，但不作为新辅导的依据来源。

## 4. 管理端流程

管理端「教材上传」替换为「知识点」。

1. 管理员可贴文本，或上传图片、常见文档和 PDF；格式与大小沿用并明确扩展现有上传限制。格式不对或过大时立即返回原因，不创建空条目。
2. 提交后创建解析任务。图片和文件先抽出可读内容，再与文本、补充提示词一起交给模型，提出若干条待确认知识点（至少标题和总结）。模型未配置或解析失败时展示明确原因，不入库空内容。
3. 确认列表中，管理员可改标题和总结、删除不需要的条目、补提示词对本次结果整批重新解析，再逐条或批量确认发布。
4. 已发布列表支持搜索、直接修改总结并保存，以及带补充提示词重新解析；新结果须再次确认后才替换已发布内容。
5. 只有管理员可创建、修改、确认和重新解析。未发布条目对任何学生接口不可见。

审计记录上传、解析、确认发布、修改已发布内容、发起重新解析；不把完整密钥或无必要的原始大文件写入审计。

## 5. 学生端与辅导

学生端去掉教材选择页和年级/科目入口，登录后直接进入学习。每日5练、知识点巩固、错题回顾、上传题目、自由提问入口保留，但不再按教材章节出题，改为依据检索到的已发布知识点出题和讲解。学生资料上传保留，不替代知识点库。

`search_textbook` 替换为 `search_knowledge`：仅在已发布条目的标题和总结中做关键词检索，返回少量最相关条目及其 ID。agent 只能引用实际返回的条目，不得把未检索到的内容当依据，也不得再引用教材、年级或科目绑定。系统提示和上下文不再注入教材对象。

## 6. 旧入口与兼容

下线教材管理、分页校对、发布教材、学生选择教材等入口。对应学生 API 和管理端新流程不再提供这些能力；旧内部服务可保留但不得从新路由暴露。旧教材表、历史文件和历史会话数据先保留，不做迁移，不对学生开放。

## 7. 错误处理

- 上传校验失败：422，说明格式或大小问题。
- 模型未配置或上游失败：解析任务 failed，管理端可见原因，不生成空条目。
- 重新解析进行中：已发布内容保持原样，学生检索不受影响。
- 检索无结果：agent 说明依据不足，不编造知识点或教材信息。
- 未登录 401；学生访问管理接口 403；访问不存在或未发布条目 404。

## 8. 测试

- 一次上传拆成多条，管理员确认后发布。
- 管理员修改已发布总结，学生检索立即看到新内容。
- 补提示词重新解析只产生待确认稿，不覆盖已发布内容；再次确认后才更新。
- 未发布条目不会被学生会话检索到。
- 学生无需选择年级、科目或教材即可创建会话并进入辅导。
- 答疑和出题会调用知识点检索；无命中时声明依据不足。
- 教材选择页、教材管理入口及相关 API 已关闭。
- 旧教材表仍存在，但学生路径不可用。

覆盖现有单元、集成和关键 e2e。不把真实密钥、完整生产教材或学生隐私写入仓库。

## 9. 非目标与后续

第一期不做向量检索、知识点之间的手工目录树、按学生授权不同知识点集、以及旧教材内容自动转换成知识点。若后续条目数量明显超出关键词检索的可用性，再单独设计向量检索。
