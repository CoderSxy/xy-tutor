# 自查引导、解题效率与自适应练习设计

- 日期：2026-11-13
- 状态：根据已讨论方向编写，待审阅；本文描述目标设计，不代表功能已经实现。
- 配套计划：[实施计划](../plans/2026-11-13-adaptive-self-learning.md)。
- 范围：分三个阶段建设可靠错因诊断与自查、动态题库与推荐、教学效果评估；解题时间贯穿三个阶段。
- 用户要求：AI 引导学生自学、提升自学能力、精准寻找不会的根源；用可操作的习惯锚点帮助学生自行发现问题；兼顾心理与信心；题目随个人水平变化；将做题时间作为能力分析依据。
- 本文提出的规则阈值、样本量及验收门槛均为工程与试点初值，不是经过本项目验证的教学结论。按版本管理，试点后调整。

## 1. 产品目标与成功定义

学生逐渐能够发现问题、检查过程、补足知识，并在没有提示时独立完成新题。AI 的价值体现为学生能力提升，而不只是辅助状态下正确率上升。

学习闭环：

`作答与有效计时 → 正误核验 → 候选错因与证据 → 自查/诊断问题 → 必要的局部讲解 → 独立变式 → 延迟复习 → 更新画像与下一题`

核心成功信号：同等知识点和可比难度下，独立新题正确率、延迟复习表现、自查质量提升，提示依赖减少；正确性稳定后，解题时间更稳定、效率提高。

### 1.1 必须遵守的教学原则

- 诊断讲证据，反馈保护自信；不能为了鼓励而把知识缺口伪装成粗心或习惯问题。
- 答案正误与错因判断独立；可以“已确认答错，但错因待确认”。
- 时间是熟练度和诊断的一个维度；不能单凭快慢判断能力、态度或错因。
- 正确性和独立性优先于速度；慢而正确不阻止知识掌握状态晋级，快而错误不获得能力加分。
- 允许求助、例子、直接讲解和暂停；不强迫学生在提示循环里反复猜测。
- 不把单次错误写成稳定人格或能力标签；不输出“笨、懒、粗心的人”等评价。
- 不因未点击、未输入而推断走神；学生可能在纸上计算。
- 学生自行发现问题必须有后续步骤修正或解释证据，不能仅凭“我懂了”认定。

### 1.2 首轮内容边界与非目标

建议首轮覆盖有理数运算和一元一次方程；以管理员确认发布的知识点定义覆盖范围，不恢复年级、科目、教材选择流程。几何条件标记等锚点可以先预置，但未经验证的几何诊断不进入自动确认范围。

本轮不做全学科自动诊断、不以摄像头或键盘行为识别注意力、不默认倒计时、不提供学生速度排行榜、不从零训练大模型、不引入独立向量数据库/Redis/推荐服务、不自动公开私人上传题、不承诺题量越大效果越好。

## 2. 当前项目与方案选择

### 2.1 已核对的基础

| 现有位置 | 当前能力 | 本次增量 |
|---|---|---|
| `apps/server/src/agent/prompts.ts` | 逐题提示；每日练习优先最终数值 | 增加需要过程的诊断分支，不再只依赖最终值 |
| `modules/learning/attempts.ts`、`assessments.ts` | 作答版本、证据与判题 | 关联过程、诊断与计时；保持原始答案 |
| `modules/learning/verifier.ts`、`practice.ts` | 数值等价、模型核验与变式关联 | 确定性模板校验、题目质量准入 |
| `modules/learning/state-rules.ts` | 原题订正、独立变式、至少 24 小时后新变式 | 保持知识掌握晋级条件；新增独立效率观察 |
| `modules/learning/knowledge.ts` | 按知识点汇总核验与独立作答 | 增加稳定知识点 ID 及分维度画像 |
| `modules/knowledge-base/search.ts` | 已发布标题/总结关键词检索 | 增加结构化知识点关系和题库筛选 |
| `modules/student-insights/**` | 活动、记录、快照与 AI 报告 | 增加诊断、自查、时间及试点评估 |

上述 `modules/` 路径均位于 `apps/server/src/`。当前 `attempts.created_at` 只是提交时间，不能推算真实解题时长。当前模型“独立核验”是独立调用，不代表统计上独立，更不构成绝对正确保证。

### 2.2 方案比较

1. 仅修改提示词：实现快，但时间、提示状态、错因和题库选择不可审计，无法可靠验证效果。
2. **采用：在现有单体中新增诊断、计时、题库与策略模块。** AI 生成候选诊断和教学表达；后端约束状态、证据、权限与推荐规则。复用 PostgreSQL、ModelGateway、JobQueue 和现有前端。
3. 立即建设复杂知识图谱、向量服务与强化学习推荐：当前缺乏校准数据，增加基础设施不能直接解决错因准确性。

本次采用第 2 项，分三个阶段交付，每阶段可以独立关闭新增能力。用户确认的是总体方向，具体参数与接口为本文的实现建议。

## 3. 三阶段交付

| 阶段 | 可交付闭环 | 时间维度的职责 | 上线前提 |
|---|---|---|---|
| 一：诊断与自查 | 过程采集、候选错因、锚点、分层提示、独立验证 | 可靠采集、分段展示、记录质量；不自动判快慢 | 隔离/幂等/降级测试通过；教师复核诊断 |
| 二：动态题库 | 审核题、受控模板、候选核验、画像与逐题选择 | 可比题个人基线；时间仅在正确性稳定后影响训练安排 | 阶段一稳定；题库准入与选择回放通过 |
| 三：效果迭代 | 教师纠错、版本追踪、试点评估、报告 | 自身效率趋势、计时覆盖与质量分层、可选群体参考 | 有足够合格样本；人工复核并签署评估记录 |

不将后阶段存在作为前阶段完成的条件；第一阶段已可通过现有生成练习服务完成独立变式与延迟验证。第二阶段再替换为可解释题库策略。

## 4. 错因诊断模型

### 4.1 错因分类

`execution_slip`（执行失误）、`condition_omission`（条件遗漏）、`concept_gap`（概念缺口）、`rule_misuse`（规则误用）、`strategy_gap`（方法选择困难）、`expression_gap`（表达/论证缺失）、`input_issue`（题干或识别异常）。

允许多个候选及一个主因；`input_issue` 未解决时不归责于学生。几何/开放证明等未覆盖题型输出 `unsupported`，不硬套数值题规则。

每个候选保存：错因代码、知识点 ID、最早错误步骤引用、支持/反对证据、待验证问题、状态、产生它的模型/提示词/规则版本。状态为 `hypothesis | supported | confirmed | rejected`；完整诊断为 `pending | needs_probe | confirmed | unsupported | invalidated`。

模型返回的置信数值不得直接作为可靠概率；第一阶段不用它晋级。`confirmed` 要求以下之一：确定性规则与可定位步骤吻合；或针对性追问/小题及原作答共同支持，且没有未解决的关键冲突；或管理员人工确认。仅根据错误最终答案、耗时、学生“我会了”不能确认错因。多原因仍可保留一个 `confirmed` 与其他候选。

### 4.2 诊断顺序

1. 校验题干确认状态、题目版本、附件可读性及已核验参考答案。
2. 复用正误核验结果；不确定则停止能力归因，先补证据。
3. 获取学生关键步骤，定位最早可确认偏差；接受合理的不同解法。
4. 生成最多 3 个候选；有证据不足时提出一次能区分候选的追问。
5. 学生回答后重新核验并追加诊断版本；不得覆盖旧结论。
6. 知识/规则缺口得到支持时直接补对应内容，不要求学生先走完“习惯检查”。

过程采集沿用文字和已有图片上传。学生可只交最终答案，但答错或诊断任务中邀请补充关键步骤；无法提供时保持证据不足，不凭空还原学生过程。OCR 结果与用户原图分别保存，识别歧义要学生确认。

### 4.3 例子

题目 `−2(x−3)=8`，学生写 `−2x−6=8，x=−7`：确认展开步骤不成立；执行失误和负数乘法规则缺口均可能。

先提示“用‘符号跟着走’检查去括号这一步”；未能修正则问 `−2×(−3)`。若单独算错，补规则；若单独算对，继续核对乘法结果如何写回原式，不能仅凭这一问就永久认定习惯问题。订正后安排独立新变式；原题正确答案为 `x=−1`。

## 5. 自查引导与教学状态

### 5.1 锚点库

| 稳定代码 | 锚点 | 具体动作 |
|---|---|---|
| `sign_tracking` | 符号跟着走 | 检查每次变形中的负号、括号和运算符 |
| `conditions_on_diagram` | 条件上图 | 已知条件标图，推导条件另行标明 |
| `write_key_steps` | 关键步骤落纸 | 易错位置写中间式，不要求熟练者永久逐步展开 |
| `restate_goal` | 先看求什么 | 重述目标，核对最终回答 |
| `align_units` | 单位对齐 | 统一输入单位并检查结果单位 |
| `balance_equation` | 两边做同样的事 | 写清等式两边进行的相同运算 |
| `check_in_original` | 答案回到原题 | 代回原条件，核对取值范围 |
| `check_preconditions` | 先查适用条件 | 说明公式和规则的适用前提 |

每条含适用错因、完整动作、首用例子、短提示、反例和内容版本。第一阶段版本化种子数据；第二阶段复用题目标签；第三阶段根据证据调整，不频繁改变学生熟悉的措辞。

### 5.2 后端状态机

`awaiting_evidence → self_check → focused_check → micro_probe → explanation → independent_check → scheduled_review`。

这是教学会话状态，不替换现有错题掌握状态。`self_check` 给锚点；`focused_check` 缩小到局部；`micro_probe` 做最小区分问题；`explanation` 局部补知识。确定有知识缺口可直接进入 explanation；学生主动请求可直接看例子或讲解。

每个未成功的检查层级最多展示一次；两次没有产生有效进展，必须提供小题、例子或讲解，不原样重复。学生新提交步骤才算一次尝试，消息刷新、重试与重复点击不计数。若小题后仍不清楚，进入讲解或转人工待处理，不无限追问。

每次动作保存输入证据、状态版本、提示级别、实际展示状态、学生回应、是否暴露答案。完整解答暴露后，该次与该题后续作答不得作为独立证据。学生稳定掌握后可减少锚点提示，但不能在缺乏新证据时宣称已形成习惯。

### 5.3 展示与暴露追踪

后端创建带版本与唯一 ID 的教学动作，前端渲染后回执，重放相同动作幂等。消息中包含解答或局部提示时，生成前登记保守的暴露类型；发送成功但回执丢失时标 `unknown`，不能当 `none`。

现有 `hints` 记录与新动作关联；作用域必须含 student、task、questionVersion。自由文本回复也需带 `exposure: none | guided | solution_exposed | unknown`；未可靠分类的回复按 unknown 处理，不能绕开工具后自动认定独立。

### 5.4 心理与交互

反馈只描述可观察行为：“你这次自己找到了展开步骤的问题”；不空泛承诺能力，不暗中做人格/心理诊断。学生端提供“补充步骤、再提示一点、看例子、直接讲解、暂停、继续”现有样式下的轻量动作。默认不展示秒数或排名，计时状态明确为“记录中/已暂停/记录不完整”。

## 6. 解题时间设计

### 6.1 指标与口径

| 字段 | 定义 |
|---|---|
| `firstAttemptMs` | 开始作答至首次提交的有效区间和；不含提交后的等待 |
| `selfCheckMs` | 首次判错反馈后，处于自查阶段的有效区间和 |
| `postHintMs` | 已展示具体提示/讲解后作答的有效区间和 |
| `totalActiveMs` | 所有有效区间并集；不得重复相加重叠区间 |
| `wallMs` | 开始至结束的墙钟时间，含暂停/等待，仅供核对 |
| `quality` | `reliable | partial | unusable`；完全未采集为 `missing` |

时间阶段互斥：首次作答期间若已接受提示，之后区间归 `post_hint`，该次不再是独立首答；`firstAttemptMs` 是首答前所有阶段合计，不能与另外两项直接相加。底层保存 `initial | self_check | post_hint` 分段及首答边界，报告按明确窗口聚合。

所有时间使用整数毫秒；UI 展示可四舍五入为秒/分钟。无数据为 null，不写 0；合法瞬时提交可为 0，但不进入效率比较。一次题目访问有一个 `episode`，重复访问不自动视为首次接触；整题总用时可跨访问聚合，效率基线只用首次接触的单次完整记录。

### 6.2 开始、暂停与结束

- 题目可见且学生点击“开始作答”后由服务端建立 episode；历史聊天里已经看过题才点击的，标记 `prior_exposure`，只作投入时间记录。
- 客户端 `performance.now()` 计算本次连续区间，不使用可修改系统时钟作为能力依据。
- 页面隐藏、主动暂停、任务切换、提交成功、开始等待 AI、断网时结束当前有效区间；只有题目可见、在线且学生恢复作答才重开。等待 AI 的区间始终不计入解题时间。
- 不采用“60 秒无点击即暂停”；前台纸笔计算可持续计时。重新可见和 AI 回复完成不自动恢复，防止把离席时间算入。
- 提交失败：网络等待暂停；保留答案，提示重新恢复或重试，不把失败标成完成。提交成功与 episode 绑定在同一服务端作答事务，回执丢失后通过幂等请求恢复。

### 6.3 心跳、缺口与多设备

- 在线可见时每 15 秒上报一次累计有效毫秒，状态变化立即上报；批次最多 20 个事件，单 episode 最多 2,000 个事件，超限关闭本段并要求恢复为新段。
- 事件包含 `eventId, episodeId, leaseEpoch, seq, segmentId, kind, cumulativeActiveMs, phase, expectedVersion`；studentId 从认证作用域推导，phase 最终由教学状态验证。
- 服务端以事件唯一键去重，序列严格递增；重试相同键同载荷返回原结果，不同载荷 409。乱序不改旧累计，409 返回可恢复快照。
- 对每个连续段，以服务端确认 start/resume 的时间为固定锚点，目标累计为 `min(客户端该段累计有效毫秒, 服务端距该段锚点时间)`；本次增量为目标累计减已确认累计，不能逐心跳分别取最小值。这样相邻心跳延迟 20 秒/10 秒时，客户端 15 秒/30 秒的累计仍可恢复为 30 秒，不会永久少计 5 秒。增量必须非负，不允许客户端直接提交最终总耗时；段封存时若仍有客户端累计被上界裁剪，该次至少 partial，不进入效率样本。服务端累计时钟异常则本段 unusable。
- 超过 60 秒未有确认、离线补报、页面异常退出或进程重启，未知缺口不计入有效时间，整次至少 partial；可保留已有确认区间。恢复建立新连续段，不把缺口补成“专注时间”。
- 同一学生最多一个活跃计时 lease；切换题目或设备须显式接管，leaseEpoch 增加，旧租约事件拒绝。lease 有效期 60 秒，心跳续租；过期后需恢复。不同设备累计不相加。
- 客户端使用唯一消费队列；SSE 重连、组件重挂和浏览器返回不重复 start。异常关闭没有最终回执时，不推算最后一段未确认时间。

`reliable` 要求 start、各阶段切换、首答/结束边界均有确认，序列完整且无缺口/争用/异常；partial 保存可用区间但不参与效率画像；unusable 仅留异常原因。这里的 reliable 表示遥测完整，并不声称能够识别离席或验证学生真实注意力。

计时故障不得阻断作答和辅导：无 episode 的旧客户端继续使用旧接口，计时质量为 missing；无法确认最终时间时正常提交答案并记录 partial。

### 6.4 可比样本与效率画像（第二阶段启用）

只选：核验正确、无提示、首次接触的新题、可靠计时、可比知识点/难度/题型/步骤复杂度、未看原题答案、未标 prior_exposure，且 `firstAttemptMs > 0`。计时伪造仍可能发生，故时间永不单独触发知识晋级或正式能力排名。

个人基线使用当前作答前最近 30 天最多 20 个合格样本的中位数；至少 5 个不同题目版本、覆盖至少 2 个日期和 2 个模板家族，否则 `insufficient_samples`。分桶键为主知识点 ID、难度档、answerType、complexityBand；不跨不相容桶强行补足样本。

`timeRatio = current.firstAttemptMs / baselineMedianMs`；初始描述区间：小于 0.75 为相对更快，0.75～1.5 为接近个人基线，大于 1.5 为相对较慢。仅生成待观察趋势，不给“能力差”标签；连续 3 个合格同桶新样本支持同一方向才影响训练目标，单题不升降档。基线与参与样本 ID 在作答评价时冻结，禁止未来数据泄漏。

正确但较慢时，优先询问耗时步骤、提供方法优化，不机械降难度；快而错误时检查审题/猜测等可能性，不能直接确认；慢且受阻时检查前置知识并提供帮助。

第三阶段可选群体参考：默认关闭；同桶至少 30 位学生、100 个合格样本且每人最多 5 个样本，才向管理员提供聚合中位数和分位数。不得向学生暴露个人比较或可识别记录；不能把群体均值写成标准完成时长。

## 7. 动态题库与知识点结构（第二阶段）

### 7.1 知识点身份与来源边界

以现有 `knowledge_items.id` 为知识内容的稳定引用。新增受审核的 `knowledge_skills` 表示可测量技能，可关联多个已发布知识点；包含代码、名称、状态和版本。`skill_prerequisites` 保存有向无环前置关系，管理员确认，自动建议不直接发布。由于知识点正文可就地修改，生成/诊断证据须冻结实际使用的标题、总结、更新时间和内容哈希，不能仅记录条目 ID 后再读取新正文冒充历史依据。

现有 `knowledge_point` 文本保留用于展示与历史兼容；新增关联 `question_skill_links`，明确一个 primary 和若干 secondary。未映射旧数据不凭文本自动合并，也不伪造历史效率；映射经人工确认才用于新推荐。

不把技能统计塞回必须带旧 revision 的模型；新建 `student_skill_profiles` 与 `student_habit_profiles`。旧知识状态接口保持兼容，允许 revision=null；本轮如触及旧 `student_knowledge_states.revision_id` 写入，应增量改可空并验证，而不是重新要求教材绑定。

### 7.2 题目元数据与准入

共享复用现有 questions/question_versions，新增 `question_bank_entries`：题目版本 ID、visibility、owner、sourceType、来源引用、skill、difficultyBand（easy/medium/challenge）、complexityBand（1/2/3）、templateFamily、内容指纹、状态和核验报告。

状态 `draft → checking → pending_review → published`，失败为 rejected，撤回为 withdrawn；只有 published 可正式推荐。人工审核题与受控模板初次发布须管理员确认。经过批准的确定性模板允许自动发布合法参数实例；纯 LLM 新题即使多次答案一致，也只进入 pending_review。已有练习服务的逐题核验路径作为阶段一兼容机制，第二阶段正式题库不等同于旧 `verification=verified`。

准入检查：条件完整/有解与取值合法；答案与评分标准；目标知识点；题干无泄露；与来源题关系；相同及近重复；内容来源可用。确定性数值模板用程序求解和边界检验；模型校验补充文字歧义，不能替代确定性可验证部分。首批模板固定为有理数运算、形如 `a(x+b)=c` 的一元一次方程，限制 a≠0，明确有理数范围；模板参数及核验器版本入库。

引用已发布知识点进行生成；无资料依据时返回 insufficient_evidence。纯生成缺少合格题时不能悄悄发布未审核题。

私人上传题默认 owner_only。共享选题条件为 visibility=shared，或 owner=currentStudent 且已通过正式准入；不能把 questions.student_id IS NULL 视为唯一的公共发布授权。进入共享库须管理员明确审核来源、脱敏并另建共享题目版本，保留授权审计，不直接改私人题 owner。

### 7.3 选题目标、难度与规则

目标为 `diagnostic | repair | transfer | review`；与现有 taskItems 的 original/variant/diagnostic 角色分开，变式关联继续验证。

优先次序：当前题闭环中的诊断/修复 → 到期复习 → 当前薄弱点修复 → 稳定技能迁移。诊断追问与微题不占每日 5 道正式题名额，但每道正式题最多 2 个微题，超过转讲解；正式练习与复习计入 5 题，跳过也不导致总安排超限。

个人初始难度配比 easy/medium/challenge：repair=60/35/5，consolidation=30/50/20，advance=15/50/35。配比在最近 20 个正式题决策中追踪，按最大缺额选择难度，不强求每天 5 题精确配平。

晋级按当前 primary skill 独立维护，只观察进入当前 trainingBand 后首次接触的新正式题，取每题首答及其最新有效核验，不能用订正后的正确替换首错。至少积累 5 个不同版本的新题，最近 5 个中至少 4 个独立核验正确，且 5 个均有可判定核验，才允许 repair→consolidation 或 consolidation→advance 一档。已消费证据 ID 与 bandEnteredAt/profileVersion 一起冻结；下一次晋级必须再积累至少 5 个进入新档后的新题，不可用同一窗口连升两档。其他技能、重做原题、微题不进入窗口。连续 2 个经核验错误只触发诊断与暂缓挑战，不凭此宣称概念缺口。未知/有提示答案不算独立正确；数据不足保持当前档，初始为 repair。已有错题掌握晋级规则仍独立适用。

时间仅在同桶连续 3 个合格观察后参与微调：正确但相对慢可插入一个方法优化目标；正确且高效可在正确率升级条件已满足时增加迁移优先级。时间不单独升降难度、不取消到期复习，也不否定正确的独立学习证据。

### 7.4 检索与排序

先 SQL 硬筛 published、权限、技能、前置要求、题型及核验，再按教学目标和 20 题难度缺额筛选；桶内按错因标签匹配数降序、首次未见优先、templateFamily 最近 5 题出现次数升序、ID 确定性排序。非复习不重复同版本，复习优先不同变式。

无候选时依次放宽模板多样性、放宽邻近难度（不得放宽权限/核验/技能前置）、排队生成受控模板实例；仍无合格题则返回 `insufficient_pool`，说明可继续讲解或等待题库补充。过程记录过滤原因，不无限重试 LLM。

索引先覆盖状态/visibility/skill/difficulty、owner、到期复习 student/dueAt、模板指纹唯一约束；依照实际 EXPLAIN 与延迟补索引，不承诺 ILIKE 等于高质量语义检索。语义召回后续单独评测。

每次推荐记录 policyVersion、候选快照、画像版本、排除原因、选题目标、难度、题目版本、时间基线引用及解释。相同 requestKey 幂等返回同一决定，重放不能读取未来画像。

## 8. 数据模型与证据生命周期

全部新增表用 UUID 主键、timestamptz、枚举 CHECK、必要 FK；学生业务记录含 student_id，按作用域查询，不依靠模型传入身份。

| 阶段 | 表/数据 | 关键约束 |
|---|---|---|
| 一 | `tutoring_episodes`、`timing_events`、`timing_segments` | episode 绑定 student/task/questionVersion；学生活跃租约唯一；eventId/seq 幂等；时间非负；追加事件 |
| 一 | `attempt_process_evidence`、`attempt_timing_snapshots` | 引用 attempt/messageVersion/附件；快照含各指标、quality、reasonCodes；不改原始答案 |
| 一 | `error_diagnoses`、`diagnosis_candidates` | 诊断版本、assessment、题目/过程版本；候选与证据；人审/规则确认来源 |
| 一 | `tutoring_states`、`tutoring_actions`、`self_check_outcomes` | 唯一状态版本；动作 requestKey 幂等；outcome 引用前后作答及核验 |
| 二 | `knowledge_skills`、`skill_content_links`、`skill_prerequisites`、`question_skill_links` | 一个 primary skill；前置 DAG；发布知识点引用有效性 |
| 二 | `question_bank_entries`、`question_templates`、`question_generation_runs` | 同版本题目准入唯一；owner 权限一致；参数/内容指纹去重；生成键幂等 |
| 二 | `student_skill_profiles`、`student_habit_profiles`、`efficiency_baselines` | 按 student/skill/桶/版本；知识/习惯/效率分别保存，证据 ID 与统计窗口完整 |
| 二 | `practice_decisions` | student/task/requestKey 唯一；候选、策略、画像、选题解释与时间引用冻结 |
| 三 | `diagnosis_reviews`、`learning_evaluations` | 纠错追加、操作者和原因；评估快照、指标口径与版本 |

episode 有多个提交边界；attempt 可选关联 episode。提交前 processEvidence 由对应用户消息版本及附件创建，不允许跨学生图片。计时快照一 attempt 一版本追加，低质量记录不覆盖可靠历史；诊断动作和结果不存内部思维链。

题目/消息修改、证据撤销、判题修正或管理员推翻诊断时，原始记录保留，新建 invalidation，受影响诊断标 invalidated；在同一事务将画像标 stale。后续推荐不得使用 stale 的派生结论，触发 PG job 按有效证据重建；失败时回退原有学习流程。历史推荐保留“按当时证据作出，现已失效”的标记，不伪装成未发生。

## 9. API、Agent 与前端边界

所有新学生接口使用 `scopeForRequest` 与 `requireStudentAccess`；管理接口仅管理员，跨学生或不可见资源返回 404。无会话 401、禁止的管理操作 403、参数错误 422、冲突 409。身份、计时累计、确认状态和 exposure 不允许模型任意指定。

第一阶段接口：

- `POST /api/tutoring/episodes`：taskId、questionVersionId、requestKey、可选接管；返回 episodeId、leaseEpoch、version、serverAt。
- `POST /api/tutoring/episodes/:id/events`：事件批次；返回已接受序列、有效累计、quality、version；租约过期/争用 409。
- `GET /api/tutoring/episodes/:id`：恢复快照，不自动开始计时。
- 扩展 `POST /api/attempts`：可选 episodeId、timingFinalEvent、processMessageVersionId；旧客户端继续可用。最终事件无效不阻断有效答案，返回 timingWarning。
- `GET /api/attempts/:id/diagnosis`：学生可理解的摘要、下一步、证据链接；不返回未筛选的候选内部文本。
- `POST /api/tutoring/episodes/:id/actions`：requestKey、expectedVersion、`request_hint | request_probe | request_example | request_explanation | acknowledge_display | pause | resume`；expectedVersion 防并发跃迁。

第二阶段：`POST /api/tasks/:id/next-practice` 幂等逐题决策；`GET /api/learning/profile` 返回有依据的分维度概览。管理员 `/api/admin/question-bank/**` 提供题目审核、模板批准、撤回，`/api/admin/learning-skills/**` 提供技能映射与前置审核。

第三阶段：`POST /api/admin/student-insights/students/:studentId/diagnosis-reviews`、`GET /api/admin/student-insights/students/:studentId/learning-evaluations`；复用现有学情页和权限语义。

Agent 工具新增 `get_tutoring_state`、`propose_diagnosis`、`request_tutoring_action`、`select_next_practice`；绑定当前学生/task/run，不能任意传其他学生。诊断服务负责模型调用与证据验证，Agent 只能提交候选。工具输出结构化有限摘要，不把整个题库注入上下文。模型超时/不可用保留已有记录与可用练习，明确提示暂不能自动诊断。

前端在 Study、QuestionCard、Composer/TutorPanel 集成当前正式题与 episode，聊天历史的旧题不自动计时。暂停与开始按钮支持键盘和读屏。沿用已确认视觉体系；本设计不授权新视觉风格重做。

## 10. 效果评估与人工纠错（第三阶段）

### 10.1 指标口径

| 指标 | 分子/分母或计算方式 | 必须分层 |
|---|---|---|
| 确认诊断精确率 | 教师认可主因的 confirmed / 已复核 confirmed | 错因、题型、确认来源、版本 |
| 诊断覆盖率 | 有 confirmed 主因的可诊断作答 / 可诊断作答 | 将 unsupported、证据不足单列，不能为覆盖强判 |
| 自查成功率 | 完整解答暴露前，经核验自行修正且有定位/解释证据的轮次 / 具备首错与自查机会的轮次 | 锚点、提示级别，退出/失败保留在分母 |
| 独立新题正确率 | 独立且核验正确的新题首答 / 独立且核验可判定的新题首答 | 排除 prior_exposure；另报全部新题中的独立首答覆盖率，提示/不确定另列 |
| 延迟复习通过率 | 到期后独立通过的新变式 / 已完成的可判定到期复习 | 同时报到期任务完成率，避免只看完成者 |
| 提示依赖 | guided/solution_exposed/unknown 的作答占比 | 区分各类，不把 unknown 当 none |
| 效率趋势 | 可比合格题首答中位数与自身冻结基线的变化 | 正确性、独立性、题桶、quality、样本数 |
| 计时覆盖/可靠率 | 有记录/全部正式作答；reliable/全部正式作答 | partial/missing/unusable 原因单列 |
| 题目质量 | 教师确认错误/歧义的已用题目数 / 复核已用题目数 | 题源、模板、核验版本 |

自查轮次与正式题分开计数；同一轮重复提交不增加分母。时间均值不替代中位数；改进不混合原题重做、不同难度或提示条件。报告样本不足时只展示事实，不生成“能力显著提升”的结论。

### 10.2 试点与门槛

首批至少 120 个教师标注样例，其中 80 个开发、40 个冻结评估；覆盖相同最终答案不同错因、七类错因、证据不足、题干误识别、不同正确解法、无计时与跨设备异常。冻结评估不得用于提示词调试；样例脱敏或人工构造，保存授权/构造说明。

第一阶段进入小范围学生试点的初始门槛：冻结集中至少 30 个系统 confirmed 诊断接受复核，主因认可率至少 90%；不足 30 不宣称达标，补独立评估样本，不提高强判率凑数。关键权限泄露、以时间单独确认错因、讲解后算独立、未知缺口算专注均为阻断项，须为 0。门槛是待验证的质量要求，不是当前成绩。

第二阶段要求已发布题准入、权限制约、无合格题降级、推荐幂等与确定性重放全部通过；题目内容由管理员批准首批题及模板后启用。

第三阶段先做描述性纵向评估；若宣称教学效果优于原流程，采用教师批准的对照方案，按学生分组、统一测评与时间窗，按需预先确定样本量并报告退出与不确定性，不把相关性当因果。未具备实验条件时不承诺提升百分比。

教师纠错新增版本，说明证据和原因，触发失效重建。可追溯提示词/模型/策略版本，便于回滚导致误判的版本。

## 11. 配置、资源与发布

新增布尔开关默认 false：`TUTOR_SELF_CHECK_ENABLED`、`LEARNING_TIMING_ENABLED`、`ADAPTIVE_PRACTICE_ENABLED`、`LEARNING_EVALUATION_ENABLED`。time 可独立采集；adaptive 依赖 self-check 与第二阶段数据迁移，evaluation 只读已有有效事实。启动时拒绝 adaptive=true/self-check=false 的矛盾配置；关闭 time 后推荐仍按正确性/独立性运行。

沿用 Node >=22.22.0、pnpm 10.30.3、现有依赖、PostgreSQL/Drizzle/PG 队列。资源基线为单实例 2 核 2GiB；题库生成/重建最多一个重任务，复用现有模型预算和限流，诊断失败不触发无限重试。

计时事件不保存按键、鼠标轨迹或屏幕截图；原始 timing_events 默认保留 30 天，聚合 timing_segments/快照与学习记录同生命周期，清理不改变已有冻结指标。清理任务按批处理，仅删已封存且已聚合事件，删除学生资料时沿用现有授权与删除流程同步处理派生数据。

迁移只增量执行；编写时最大编号 0022，实施时重新检查，更新 Drizzle journal，不覆盖旧迁移、不 reset 数据库。历史未计时的数据保持 missing，不回填推算耗时。

发布顺序：迁移与兼容后端 → 开关关闭部署 → 管理员审核内容 → 第一阶段白名单试点 → 第二阶段策略影子运行/人工核对 → 开启推荐 → 第三阶段评估。回滚关闭功能开关、保留证据与历史结构，继续原有学习流程；不做破坏性回滚迁移。

## 12. 验收与参考依据

验收必须覆盖确定性单元测试、真实 `_test` PG 集成、浏览器 e2e；计时用虚拟时钟和固定事件，不依赖真实等待。真实模型 smoke 与教师内容评估独立记录，不能用 mock 测试通过代表教学质量通过。

首要旅程：首次独立错答 → 可靠计时 → 锚点自查 → 必要追问/讲解 → 独立新变式 → 至少 24 小时后新变式 → 分维度画像 → 下一题解释；以及相同旅程在无模型、无计时、断网和功能关闭时的可用降级。

参考研究支持将“有帮助时表现”和“独立表现”分开，并采用主动提取、间隔练习和解释性提问；不用于证明本文阈值：

- [Bastani 等：Generative AI Without Guardrails Can Harm Learning](https://hamsabastani.github.io/education_llm.pdf)。
- [IES：Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/WWC/PracticeGuide/1/Published)。
