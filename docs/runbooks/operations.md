# 日常运维与容量

`sh scripts/resource-smoke.sh`读取磁盘、Compose容器内存和健康状态；它不会创建学习数据或自动压测。上线后在测试账号发起两路流式会话、上传一份知识点资料形成单个解析队列，再执行该脚本并记录峰值。观察整个Node容器而非仅父进程RSS；记录docker stats、OOMKilled、PG连接数、CPU、请求耗时、事件循环延迟与上游并发。

当前限制：每会话一个运行、模型请求全局2并发、后台任务单并发、PDF逐页；后台任务有租约/心跳/最多3次尝试。重启后中断的Agent运行保留已写事件，不重放工具副作用，学生可以继续发起新消息。解析任务租约到期后重试。修改已发布知识点立即影响后续检索；旧会话保留当时引用。

磁盘低于20%：告警并检查备份缓存、Docker镜像和日志（按10MB×3轮转）；清理前确认内容归属。低于10%：资源保护暂停后台解析。容器通过RESOURCE_DISK_PATH挂载只读resource_disk卷查看Docker数据盘空闲，而不是只看/tmp的独立tmpfs；部署时Docker数据目录应位于待监控的40GB数据盘。可用内存不足128MiB或Node RSS达到512MiB也暂停新后台任务。恢复空间/内存后自动继续排队。原件和长期备份放OSS；不可把PG卷、学生历史或原始资料当缓存删除。

建议主机监控：磁盘<20%、内存持续高、容器重启/OOM、ready失败、队列最老任务超过10分钟、任务失败、备份超过26小时。应用不记录内部思维链；数据库保存可观察工具、引用、结果和模型版本。生产诊断日志不得包含密码、API Key、Cookie、签名URL或学生原文。

第一阶段增加用户时先监控后升级：2核4GiB优先缓解内存；再考虑拆出RDS、对象生命周期和队列独立worker。不使用每个学生一个常驻pi进程。
